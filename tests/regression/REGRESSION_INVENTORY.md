# Regression inventory (KOS-SENSE-010)

Status: written before the tests it governs (AC-1001). Every mandatory regression case is a row of the table below. Each test module names the case it protects with a `REGRESSION = "REG-nn"` class attribute. `scripts/regression_gate.py` fails when a listed case has no passing test, when a test belongs to no listed case, when zero tests ran or the run was incomplete; `tests/regression_gate/` checks the inventory against the tests in both directions and checks that every test and source named here exists.

What counts as a regression, and what needs a contract version, a changelog entry and a central decision, is written in [README.md](README.md). All input is synthetic and generated from fixed seeds or taken from the fixtures of the earlier tasks. A regression test protects a documented contract, a fixed defect or an accepted external behaviour (exit codes, diagnostics, options, output bytes); it never protects an internal function or an incidental detail.

How the expected values come about: the stream cases use the hand-written `tests/stream/fixtures/expected.json`; each Sense and frame graph invalid fixture carries a hand-written `expected_codes` that the tests compare with the golden violations; the remaining golden data under `golden/` record the behaviour accepted in KOS-SENSE-001 to KOS-SENSE-009 and change only through `scripts/regenerate_regression_golden.py` (README).

## Notes for review

- The regression tests are not a second copy of the unit suite. The unit tests check behaviour in detail; a regression case pins what an outside user or a contract can rely on, usually through the command line, and fails with a message that names the rule to follow.
- F-004 to F-011 of KOS-SENSE-008 are not listed: F-004 and F-005 are repository policy protected by `tests/security` and the workflow tests, F-006 and F-009 by the policy test, F-007, F-008 and F-011 were accepted risks, and F-010 was a documentation correction. The earlier reviews recorded no other fixed defect that a test can protect.
- `make test-regression`, the aggregate `make test` (`scripts/test_all.py`, tested with stand-in gates in `tests/regression_gate/test_aggregate.py`) and the CI step "Regression gate" were added by the separate owner-merged protected-path pull request of this task.
