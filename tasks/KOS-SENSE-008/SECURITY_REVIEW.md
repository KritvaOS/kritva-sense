## 1. Scope, method and limits

Scope: the threat model entry points EP-1 to EP-16 of the repository as it is. Method: reading the code and the workflows; probing the command lines with crafted inputs (malformed, empty, binary, very large, deeply nested, wide, huge integers, NaN, invalid UTF-8, missing files, directories, symbolic links); loading controlled temporary consumer modules in separate interpreters; an automated policy check of every workflow; inspection of the build configuration and of the contents of the release artifacts; running every test suite with the network disabled. Each statement that can be tested is covered by a test in `tests/security/`; the test name is given in the register or in the section.

Limits: an internal review of a small standard-library-only code base by its own team. No external scanner, fuzzer or dependency auditor was part of acceptance (the runtime has no dependency to audit). No test of the GitHub-hosted settings that are not in the repository (branch protection, rulesets, private vulnerability reporting, secrets stored in the settings): they are stated as unverified. Only Linux and Python 3.12 were exercised.

## 4. Review by area

### Input handling (AC-802)

Entry points EP-1 to EP-4. Malformed, oversized, deeply nested, wide input and path misuse were probed. One defect class (F-001, deep nesting) and one resource bound (F-003) were found and fixed; the rest are confirmed non-issues (N-1 to N-5). The decoder's recursion limit is a property of the Python standard library: JSON nested beyond about a thousand levels is rejected as unreadable (exit 2). Documents larger than memory are not specially handled: the commands read a file completely, as their documentation says.

### Consumer loading (AC-803)

Entry point EP-5. The cases tested with controlled temporary modules written by the tests, each in a separate interpreter: a valid consumer object, class and factory; a module that raises, calls `sys.exit()` or contains a syntax error at import; a missing attribute; an attribute that is not callable or is `None`; a consumer missing an operation; a factory that raises or exits; a consumer that raises or exits when invoked; a hostile decision object; two consumers of which one fails; a consumer and a module that hang (the child is ended by a subprocess timeout that belongs to the test); invalid specifications. **Loading is not a sandbox.** The imported module runs in the harness process with the privileges of the user; a timeout, where an operator adds one, ends the process and does not isolate or make the consumer safe. The documentation (`src/kritva_sense/CONFORMANCE.md`) and this report say so. No untrusted code was run.

Runtime dependencies are empty, the runtime imports only the standard library (N-6), and the build configuration is hash-pinned (N-7). This task changes five of those packaged files (`__main__.py`, `frame_graph.py`, `stream.py`, `conformance.py`, `generator.py`: the fixes F-001 to F-003), so the package built from the closing commit of this task is not byte-identical to the 5f1aa7a artifacts. Offline requirement. The mandatory suites pass with the network disabled: `tests/security/test_offline.py` runs the contract, frame graph, generator, stream, conformance, status and security suites with socket connections and name resolution blocked, and runs the packaging suite with a prepared wheelhouse (`KRITVA_WHEELHOUSE`) and a dead package index; every mandatory packaging test executes. ## 6. Final report

Conclusion. The repository's commands, consumer loading, workflows and build path were reviewed against the threat model. Three defects (two Medium, one Low) and one documentation gap were fixed with regression tests; two further findings have fixes in an owner-merged protected-path pull request; five Low or Medium findings need the risk owner's disposition. Each statement in sections 3 and 4 is backed by a test or by the named review step.

Explicit non-claims. This review is **not a certification**, a penetration test or an audit by an independent party. The consumer loader is **not a sandbox**, and a timeout does not make it one. The review makes **no safety claim**: nothing here concerns hardware, a sensor, a robot or operational safety, and it does not show that the repository is free of vulnerabilities; it records what was examined, what was found and what was done. The review is the interim D-047 role and is not independent for the task itself. It does not verify the settings that live outside the repository files. The test data are synthetic.

Evidence. `make test-unit` and `tests/security/` pass in CI on the closing commit and in a network-disabled run; the run identifier, the closing commit and the retest evidence for each fixed finding are recorded when the task is submitted for review.
